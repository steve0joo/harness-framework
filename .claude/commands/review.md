이 프로젝트의 변경 사항을 리뷰하라.

먼저 다음 문서들을 읽어라:
- `/CLAUDE.md`
- `/docs/PRD.md`
- `/docs/ARCHITECTURE.md`
- `/docs/ADR.md`

그런 다음 변경된 파일들을 확인하고, 아래 체크리스트로 검증하라:

## 체크리스트

1. **아키텍처 준수**: ARCHITECTURE.md에 정의된 디렉토리 구조를 따르고 있는가?
2. **기술 스택 준수**: ADR에 정의된 기술 선택을 벗어나지 않았는가?
3. **테스트 존재**: 새로운 기능에 대한 테스트가 작성되어 있는가?
4. **CRITICAL 규칙**: CLAUDE.md의 CRITICAL 규칙을 위반하지 않았는가?
5. **MVP 범위**: PRD의 "MVP 제외 사항"에 있는 것을 구현하지 않았는가?
6. **에러 처리·보안**: ARCHITECTURE.md "에러 처리·보안"의 필수 항목과 CLAUDE.md CRITICAL 규칙을 지켰는가?
7. **검증 명령**: CLAUDE.md "명령어"에 정의된 lint, build, test를 프로젝트 루트에서 실제로 실행해 통과하는가? 정의되지 않았거나 placeholder(`{...}`)로 남은 명령은 실행하지 말고 `미확인 (사유)`로 적는다.

## 출력 형식

| 항목 | 결과 | 비고 |
|------|------|------|
| 아키텍처 준수 | ✅/❌/미확인 | {상세} |
| 기술 스택 준수 | ✅/❌/미확인 | {상세} |
| 테스트 존재 | ✅/❌/미확인 | {상세} |
| CRITICAL 규칙 | ✅/❌/미확인 | {상세} |
| MVP 범위 | ✅/❌/미확인 | {상세} |
| 에러 처리·보안 | ✅/❌/미확인 | {상세} |
| 검증 명령: lint | ✅/❌/미확인 | {실행한 명령과 결과, 또는 미확인 사유} |
| 검증 명령: build | ✅/❌/미확인 | {실행한 명령과 결과, 또는 미확인 사유} |
| 검증 명령: test | ✅/❌/미확인 | {실행한 명령과 결과, 또는 미확인 사유} |

판정 기준이 문서에 없거나 placeholder로 남아 있으면 `미확인 (사유)`로 적는다.

위반 사항이 있으면 수정 방안을 구체적으로 제시하라.
